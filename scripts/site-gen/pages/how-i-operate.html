How I operate · rules, receipts, and the fleet

I don't write the code. I direct the people and the agents who do, and I hold the bar.

Being an AI-driven leader comes down to a set of operating rules. Each one below carries the moment it was tested. Underneath the rules: the seven-agent fleet that runs my operating work, and the things built under my direction.

Six rules

Each one has a receipt.

  1. Direct, don't do.

    Agents write the code and the drafts. Emma, my principal engineer agent, ships the software. My job is to diagnose the actual problem, give clear direction, and hold the line on quality until the fix is proven, not claimed.

    receipt: an early build of my goals dashboard looked finished but hid broken states behind a clean screen. I sent it back for a full rebuild. A demo that hides broken states isn't a working system.

  2. Interview before you task.

    Context, role, interview, then task. Give the AI the context and the role, then have it interview you before it produces anything. The output is better because the question got better. Credit where it's due: Geoff Woods, The AI-Driven Leader.

    receipt: this site's redesign came out of a ten-question interview I had my AI run on me, one question at a time, before a line of it was built. Two of my own assumptions didn't survive it.

  3. Cost is policy, not preference.

    Model spend is governed in the build, not reviewed in a spreadsheet after the fact. A written rule decides when to add a new agent versus extend one, so the fleet doesn't sprawl.

    receipt: the build fails if an unannotated top-tier model call appears on a mechanical or scheduled path.

  4. A human approves every send.

    Agents draft. People decide what leaves the building. Only one agent talks to people at all, and integration ownership follows the home system so five services don't hold the same credential.

    receipt: 0 autonomous sends across seven production agents. A security review found and closed a SQL injection and a token-refresh blind spot that had left monitoring falsely healthy.

  5. Presence beats outbound.

    Go where the buyers already are, bring the expert, show the sample. The point of the agent savings is to afford being in the room.

    receipt: events were 59% of G2i's Q2 2026 leads (1,075 leads). Local-first beat email on response rate at The Agent Company.

  6. Catch what fails quietly.

    The hard failures announce themselves. The expensive ones don't. Idempotency guards so a scheduled job can't double-fire, optimistic concurrency after a data-safety review, and postmortems written down.

    receipt: a nightly pipeline had 404'd silently for weeks with monitoring reporting green. Root-caused, fixed, and the blind spot in the monitor closed with it.
The fleet

Seven agents run the operating work of my job.

Reporting and pipeline analysis, chief-of-staff duties, marketing and social-selling drafts, and the internal tooling I run from: wikis, dashboards, the revenue brain. Each agent is its own cloud service with its own tests, migrated into a monorepo with a documented rollback plan and a health-gated cutover.

The flagship is the Rocks dashboard. I run my quarterly goals off it and twice a week it drafts the leadership standup. Spec before code, relational SQL chosen over key-value with the reasoning written down, and a Box-note sync and a spreadsheet removed so there's one source of truth.

What's public. The shared memory engine every agent builds on is open source: full git history, 75 tests, and it never touched business data. severs-agent-shared on GitHub. The rest of the fleet stays private.

For the technically curious

The stack, and one trust boundary.

Turborepo and Bun workspaces, TypeScript on the native compiler, and Effect Schema enforced at every trust boundary: model output, external APIs, HTTP bodies, and the shared memory engine's write path. Correctness-only lint blocks CI. A supply-chain rule sets a seven-day minimum publish age on new dependencies so a same-day-published package can't be pulled in by accident.

The snippet is the shape of every model call in the fleet: the reply is decoded against a schema before anything downstream can touch it, and a bad reply throws instead of silently propagating malformed data.
